# P04 Phase 回归修复记录

本记录对应 `acceptance/p04`，不是 Phase 放行结论。原始失败证据保留在 Harness 的
`state/acceptance/p04-phase-20261022-2/`，不覆盖、不删除历史失败。

## 生产缺陷

1. **Runtime 用量事件字段漂移**：报告校验器接受缓存、推理等 P04 字段，但事件
   白名单仍使用旧字段集，导致规范化后的合法用量被拒绝。两处改为共享字段集；
   字段值仍由原有校验器校验，未知字段仍拒绝。新增 round-trip 回归。
2. **Host 能力漏报**：`execution.stop.manual` 已有 Core 命令及 Host 路由，却未在
   Host 能力列表声明。补齐声明，不扩展授权范围。
3. **停止核验负结果永久缓存**：首次确认窗口内进程组未消失，后续恢复一直复用
   `confirmed=false`。保留单次升级信号的身份记录，后续仅重新清点组成员；
   身份不匹配不重新探测为成功，不重复发送已送达的 SIGKILL。
4. **macOS 退出过渡**：`ps` 在 argv 暂不可读时可能仅返回 `(node)`，且状态仍
   为 `Ss`。将其记为未知并在既有窗口内只重读，不视为有效启动身份或停止证明。
   僵尸状态单独识别，但仍清点整个进程组；投递失败后的自然退出必须有新的监督者
   缺席及组缺席证据，不能靠信号失败本身推断停止。

- 当前完整迁移已到 v34，旧测试及 P01/P02 验收配置仍预期 v30。集中维护当前
  schema 版本预期，保留历史版本的 SQL/checksum、数据保留及回滚断言。
- 完整库包含录制及调度表；更新当前表清单，继续检查空库没有执行记录。
- P04 的 Pi SDK 只允许在指定 Host 适配文件导入；Core/CLI 独立性、SDK 精确
  版本、非适配文件禁入与禁止依赖检查仍保留。
- 收尾重试夹具必须具备完整停止证据：无事件的确定性夹具记录水印 0，多 Task
  夹具的当前工作区绑定到最后一个 Attempt。不能通过放松启动隔离来修复夹具。
- 路径别名测试显式创建符号链接，不再假设临时目录必然经过 `/var` 别名。
- 超时测试的 PID 文件通过临时文件加 rename 发布，避免读取到半写的 JSON。
