# P04 验收控制器内存修复

适用范围：`scripts/acceptance/owned-process-tree.ts`，仅验收工具，不改变 Core
Runtime、租约、锁、超时或 Phase 放行策略。

## 故障与复现

2026-10-22 首轮 P04 阶段入口运行约 46 分钟后堆内存耗尽，未取得完整测试结论。
进程采样器长期累积历史 PID/身份；身份字符串还间接引用整份 `ps` 输出。
旧实现每轮对每个进程线性查找父进程，扫描成本也随进程表增大。

最小实验模拟 201 次采样，每次含一个 512KiB 无关 argv 和一个短命子进程：

| 实现 | GC 后堆增长 | 保存身份数量 |
| --- | --- | --- |
| 修复前 | 100.59MiB | 202 |
| 修复后 | 0.55MiB | 2 |

这验证进程表字符串保留与历史身份增长，不代表完整阶段测试已通过。
复现脚本及原 OOM 日志保存在 Harness `state/recovery/` 和
`state/acceptance/p04-phase-20261022-1/`。

## 修复边界

- 身份改为启动时间与完整 argv 的 SHA-256 摘要，不保存整份历史进程表的字符串引用。
- 仅在成功采样后裁剪已消失、僵尸或身份变化的历史记录；仍存活的已证实孤儿保留。
- 父子关系索引与队列代替反复线性查找；所有新归属仍必须来自已证实父进程。
- 根 PID 只在首次身份探测时绑定，退出后不因 PID 复用或首次探测失败而重新认领。
- 清理前仍重核 PID、启动时间和 argv 摘要；扫描失败仍使停止核验失败，不能假装清理成功。

定向回归包含内存保留、短命进程裁剪、乱序子树、孤儿、PID 复用、argv 变化及扫描失败，
并复验真实进程清理、P04 步骤器、入口和报告。完整阶段验收须在修复提交上以新 run-id
独立执行，旧失败证据不覆盖，真实模型验证与人工确认仍单独进行。
