# 阶段验收与全仓回归

阶段默认验收当前阶段测试、受影响基础模块和必要跨层冒烟、类型/构建；可信索引必须完整校验，但历史引用不等于每次都全量执行。
全仓历史矩阵按显式请求运行，不是每个Phase默认前置条件。

```bash
# P04阶段范围：类型/构建 + P04索引合集
npm run accept:p04 -- --run-id <new-id>
# 显式全仓模式
npm run accept:p04 -- --run-id <new-id> --full-gate
# 独立全仓工程门禁（原有语义）
npm run verify
```

默认阶段模式会明确记录全仓测试not_run。observe须沿用原模式，full-gate与默认模式的输入摘要不同。
阶段模式不代替live或人工批准；Phase完成也不因一条脚本退出0自动成立。

Git/worktree重量测试按影响运行：修改对应实现、并发、锁或恢复时运行其故障矩阵；
普通查询或规划变更不自动重跑所有历史Git场景。数据库迁移变更必须跑升级/回滚/约束回归。

P04一次历史门禁约40.7分钟，light约4秒、standard约30秒，heavy 270文件是主要成本；
workspace-discard约459秒，controlled-git-commit约391秒，workspace-cleaner约380秒。
全仓后又执行P04合集存在重叠。全仓10～20分钟为优化目标，尚未实测达成。

后续优化先对慢文件拆分资源准备、迁移、Git、构建、等待和清理计时；再安全复用同运行只读构建产物、
评估预迁移模板复制与矩阵去重。保持每例可写资源隔离，专测迁移与崩溃窗口的路径不可省略。
不通过增加超时或删除故障断言制造提速。此次仅验证入口定向回归，不重新执行全仓。

P05 默认范围由 `scripts/acceptance/p05-test-scope.ts` 显式列出：保留全部 P05 测试及必要底层回归，其他可信索引历史文件逐项写入 `test-scope.json` 的 deferred 列表，状态为 not_run。清单同时进入报告证据；不删除测试，不将后置项记为通过。默认预算为单步 15 分钟、总计 20 分钟，实际耗时另以执行记录为准。
