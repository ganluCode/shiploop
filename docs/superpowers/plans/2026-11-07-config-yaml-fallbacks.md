# YAML 配置与有序备用模型实施计划

范围：兼容原 JSON 输入，新增 YAML；二者支持相同的每策略 fallbacks 和 fallbackPolicy；标准 Pi 装配接入现有 Core 降级服务；显式文件监视；Skill 提供项目根目录模板。默认单 Agent，不调用真实模型，不提交或 push。

## 设计边界

- RuntimeStrategyV1 保持单模型调用契约。ConfiguredRuntimeStrategy 扩展配置与 Task 策略快照，保存有序且不嵌套的备用策略（最多 32 项）、可选失败切换政策；禁止重复主/备模型身份。
- Task 创建/显式重新应用时冻结备用链。当前 Task 及已批准的旧 Task 不因配置文件变化被悄悄改写；每个新 Task 从其首选策略开始，返工使用原冻结链。
- 配置保存时验证所有主备模型能力；运行前重新核验目录、凭据和端点。限流切换；连接/服务端失败先耗尽既有重试。只有旧执行停止确认、必要证据完整且预算允许才创建备用 Attempt，保留代码/工作区。全部不可用停止。
- JSON/YAML 共用 Core 配置校验和数据库命令。YAML 使用受限安全解析，拒绝重复键、别名扩展、未知标签、过大文件和多文档，不使用正则模拟解析器。
- config watch 是用户显式开启的 CLI 进程：保存即通过 Host 的标准 create/update 与 CAS 同步当前项目设置。写坏或冲突告警、不覆盖数据库最后有效值，不启动执行、不自动增加预算或通过人工门禁。重放沿用原命令 ID，未知结果先查回执。Ctrl+C 只结束观察进程。
- 未配置备用链时行为不变。不把 SDK reported ready 当作连通性通过；不调用外网探测。限流恢复时间未知时下一个新 Task 再走首选；可信恢复时间的持久冷却涉及额外事实来源，未接入时不伪造重置时间或宣称跨 Host 生效。

## 工作项

1. Core：配置 Schema、有效设置、Task 副本、能力校验和策略规范化，保持单模型 Runtime 协议不变。测试旧 JSON、配置拒绝、顺序及冻结。
2. Host/Core：标准 Pi failureRouting 与受控切换接线；验证失败分类、停止/录制边界、主备顺序、无备用兼容和新 Task 首选重置。只使用离线假服务。
3. CLI：引入已有锁定版本的 YAML 解析依赖；create/update 支持 YAML 和 JSON；新增 config watch 的解析、帮助和执行层，复用标准 Host 命令及 CAS。测试坏文件、重复保存、版本冲突和停止。
4. Skill/文档：增加 templates/shiploop.yaml 与生成说明，加入 init 同步清单；说明只写凭据引用、主备顺序和使用限制。相关定向回归、类型/边界检查、构建验证，不跑全量门禁。
