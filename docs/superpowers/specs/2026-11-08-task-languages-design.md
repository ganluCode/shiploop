# Task 开发语言字段

为后续按语言拼装 Prompt 提供正式执行依据。采用 `languages: string[]`，支持单语言与多语言，
通过既有计划导入、修订及规划候选批准接口写入；本轮不增加任务类型，也不实现 Prompt 模板拆分。

- 省略兼容为 `[]`，非代码任务或语言未知时使用空数组；不猜测回填历史任务。
- 开放语言名称集合，不限制固定语言枚举；最多 16 项，每项 trim 后 1～64 字符，
  不含控制字符，转小写、去重、排序。不进行别名推断，框架名称不充当语言。
- SQLite 迁移 v66 增加 `tasks.languages` JSON 数组列，默认 `[]`；ORM、正式写入、
  Task 查询、规划候选查询及 Host 客户端同步支持。
- 非空语言参与 planDigest、执行快照、Prompt、manifest 中 Task 来源身份及恢复输入比较；
  空数组在摘要和 Prompt 投影中省略，保持旧计划和旧执行输入身份兼容。
- Planner 被明确提示填写该字段；实际输出仍由正式契约校验，提示词不能代替校验。
- 选择正式字段而非 labels，是因为 labels 不参与业务批准身份；选择开放数组而非单值枚举，
  是为了支持多语言项目与 DSL，并避免每增加语言都迁移 Schema。

验证范围：输入负例与规范化、摘要兼容、真实 SQLite 导入和修订、候选批准、Host 查询、
执行输入制品、旧库升级和恢复时输入变化；不发送真实模型请求，不跑全仓测试。
